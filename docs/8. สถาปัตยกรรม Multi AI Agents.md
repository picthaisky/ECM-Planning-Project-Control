# **สถาปัตยกรรม Multi AI Agents สำหรับ CM+ Project Control**

## **AI Agent Team Architecture Blueprint (Implementation Spec)**

เอกสารนี้คือพิมพ์เขียวของระบบ Multi AI Agents ที่ถูกติดตั้งจริงในโปรเจกต์นี้ (ไดเรกทอรี `.claude/`) ออกแบบตามเอกสารข้อ 7 (โครงสร้างทีมงาน) และขยายให้ครอบคลุมทุกมิติของการพัฒนาระบบ CM+ Project Control ตาม Best Practice ของ Claude Code

### **2. องค์ประกอบของระบบ (System Components)**

| องค์ประกอบ | ตำแหน่งไฟล์ | หน้าที่ |
| :---- | :---- | :---- |
| **Orchestrator Rules** | `CLAUDE.md` | รัฐธรรมนูญของทีม: บริบทโปรเจกต์, กติกาการมอบหมายงาน, pipeline อัตโนมัติ |
| **AI Agents (11 ตัว)** | `.claude/agents/*.md` | ผู้เชี่ยวชาญเฉพาะทาง แต่ละตัวมี system prompt, tools และ model ของตัวเอง |
| **Skills (ทักษะ)** | `.claude/skills/*/SKILL.md` | ความรู้เชิงปฏิบัติที่โหลดเมื่อจำเป็น (Progressive Disclosure) และเรียกผ่าน `/ชื่อskill` ได้ |
| **Knowledge Base** | `.claude/knowledge/` | คลังความรู้ถาวร: สูตร EVM/CPM, ADR, บทเรียน, แบบแผนโค้ด |
| **Self-Learning Loop** | `knowledge-curator` + `/learn` | กลไกเรียนรู้อัตโนมัติหลังจบงานสำคัญทุกครั้ง |

### **4. โปรโตคอลการประสานงานอัตโนมัติ (Coordination Protocol)**

การส่งงานระหว่าง Agents ใช้ **Artifact Handoff Pattern** — ทุก agent สื่อสารผ่านไฟล์มาตรฐานใน repo (ไม่ใช่บริบทลอยๆ) ทำให้ตรวจสอบย้อนกลับได้เสมอ:

```
คำขอฟีเจอร์ (มนุษย์)
   │
   ▼
[1] po-analyst        → เขียน docs/specs/<feature>/story.md (User Story + AC)
   ▼
[2] domain-expert     → ตรวจ/เติมสูตรและกฎธุรกิจ → docs/specs/<feature>/domain-rules.md
   ▼
[3] system-architect  → ออกแบบ → docs/specs/<feature>/design.md + ADR ใหม่ (ถ้ามี)
   ▼
[4] backend-developer ─┬─ ทำงานคู่ขนาน (parallel) ─┬─ frontend-developer
    database-engineer ─┘                          │
   ▼                                              ▼
[5] qa-engineer       → เขียน/รัน test ทั้งหมด รายงานผลจริง
   ▼
[6] code-reviewer + security-auditor (คู่ขนาน) → findings ต้องถูกแก้ให้หมด
   ▼
[7] knowledge-curator → สกัดบทเรียนเข้า .claude/knowledge/ (Self-Learning)
   ▼
ส่งมอบ (มนุษย์ approve ก่อน merge — Human-in-the-loop ตามเอกสารข้อ 7)
```

Pipeline นี้ถูก encode ไว้ใน skill `/feature-pipeline` — สั่งครั้งเดียว Orchestrator จะไล่ครบทุกขั้นอัตโนมัติ

**กติกา Handoff:**
1. ทุกขั้นต้องผลิต artifact เป็นไฟล์เสมอ ก่อนส่งต่อขั้นถัดไป
2. Agent ปลายทางต้องอ่าน artifact ของขั้นก่อนหน้า + `.claude/knowledge/INDEX.md` ก่อนเริ่มงาน
3. งานที่อิสระต่อกัน (BE/FE) ให้รันคู่ขนานเสมอเพื่อความเร็ว
4. ขั้น QA/Review ไม่ผ่าน → ตีกลับขั้น [4] พร้อม findings จนกว่าจะผ่าน (สูงสุด 3 รอบ แล้ว escalate หามนุษย์)

### **5. ระบบเรียนรู้ด้วยตัวเอง (Self-Learning System)**

```
 ┌──────────────┐     ┌──────────────────┐     ┌───────────────────────┐
 │  ทำงานเสร็จ    │ ──► │ knowledge-curator │ ──► │ .claude/knowledge/     │
 │ (feature/bug) │     │  วิเคราะห์ diff,    │     │  lessons, patterns,    │
 └──────────────┘     │  บทสนทนา, ผลเทส   │     │  decisions (ADR)       │
                      └──────────────────┘     └───────────┬───────────┘
                                                           │ ถูกอ่านโดยทุก agent
                              ┌────────────────────────────┤ ในงานถัดไป
                              ▼                            ▼
                   ┌──────────────────┐         ┌──────────────────┐
                   │ อัพเดท SKILL.md   │         │ อัพเดท CLAUDE.md  │
                   │ เมื่อพบ pattern    │         │ เมื่อพบกติกาใหม่    │
                   │ ที่ใช้ซ้ำ ≥ 2 ครั้ง  │         │ ที่ต้องบังคับใช้ทั้งทีม │
                   └──────────────────┘         └──────────────────┘
```

* **Trigger อัตโนมัติ:** CLAUDE.md สั่งให้ Orchestrator เรียก `knowledge-curator` หลังจบงานสำคัญ (feature เสร็จ, แก้บั๊กที่ไม่ trivial, การตัดสินใจสถาปัตยกรรม)
* **Trigger ด้วยมือ:** ผู้ใช้พิมพ์ `/learn` เมื่อไรก็ได้เพื่อบันทึกบทเรียนทันที
* **การยกระดับความรู้ (Knowledge Promotion):** บทเรียน → ถ้าถูกใช้ซ้ำ ≥ 2 ครั้ง → เลื่อนขั้นเป็น Pattern ใน skill → ถ้าเป็นกฎที่ทุกงานต้องทำตาม → เลื่อนขั้นเข้า CLAUDE.md
* **การป้องกันความรู้เน่า (Knowledge Decay Control):** curator ตรวจและลบ/แก้ความรู้ที่ล้าสมัยทุกครั้งที่เข้าไปเขียน (เช่น library เปลี่ยนเวอร์ชัน, ADR ถูก supersede)

### **6. หลัก Best Practice ที่ระบบนี้ยึดถือ**

1. **Single Responsibility per Agent** — agent หนึ่งตัวเก่งเรื่องเดียว ลด hallucination และ context pollution
2. **Progressive Disclosure** — ความรู้หนัก (สูตร, spec) อยู่ใน skills/knowledge โหลดเมื่อใช้ ไม่ถ่วง context
3. **Artifact-based Communication** — ทุก handoff เป็นไฟล์ ตรวจสอบย้อนกลับได้ 100%
4. **Fan-out Parallelism** — งานอิสระรันคู่ขนาน (BE ∥ FE, review ∥ security)
5. **Human-in-the-loop** — มนุษย์ approve การออกแบบและ merge เสมอ (ตามเอกสารข้อ 7 หัวข้อ 3)
6. **Verification over Trust** — QA ต้องรันเทสจริงและรายงานผลจริง ห้าม agent อ้างว่าผ่านโดยไม่มีหลักฐาน
7. **Compounding Knowledge** — ทุกงานทิ้งความรู้ไว้ให้งานถัดไป ทีมเก่งขึ้นแบบทบต้น
