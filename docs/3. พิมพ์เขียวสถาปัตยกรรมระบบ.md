### **2\. การแบ่งเลเยอร์ของ Backend (.NET 10 Clean Architecture)**

#### **A. Domain Layer (แกนกลางของระบบ \- ไม่พึ่งพาใครเลย)**

* ประกอบด้วยหน่วยข้อมูลหลัก (Entities), ค่าข้อมูล (Value Objects), ขอบเขตและกฎทางธุรกิจ (Domain Invariants/Rules) และ Exception เฉพาะของระบบ  
* *ตัวอย่าง:* คลาสหลัก Project, Activity, WBSNode, Baseline

#### **B. Application Layer (ควบคุมการไหลของข้อมูลและธุรกิจระดับระบบ)**

* ประกอบด้วยคำสั่งประมวลผล (Use Cases), ระบบแยกคำสั่งเขียนและอ่านข้อมูลออกจากกัน (CQRS pattern ด้วย MediatR), และคลาสสัญญาระหว่างส่วนงาน (Interfaces)  
* *ตัวอย่าง:* คำสั่งสร้างกิจกรรม CreateActivityCommand, ตัวจัดการดึงข้อมูล WBS GetWbsTreeQueryHandler

#### **C. Infrastructure Layer (การติดต่อกับสภาพแวดล้อมภายนอก)**

* บรรจุการทำงานกับเทคโนโลยีที่ใช้จริง ได้แก่ Entity Framework Core DBContext, การติดต่อกับ MSSQL Server, ระบบส่งออกไฟล์ PDF, ระบบจัดเก็บรูปภาพ และบริการเชื่อมต่อภายนอก (เช่น ไลบรารีอ่านไฟล์ MPP และ XER)

#### **D. Presentation Layer (จุดเชื่อมต่อสำหรับส่วนหน้าบ้าน)**

* รับคำขอจากภายนอก ส่งต่อเข้าสู่คลาส Use Case และแปลงผลลัพธ์กลับเป็น JSON หรือส่งคืนไฟล์เอกสาร (เช่น PDF หรือ Excel) ให้กับไคลเอนต์

### **3\. รายละเอียดสถาปัตยกรรม Frontend (React 19 PWA)**

การจัดเตรียมและดูแลโค้ดฝั่งหน้าบ้านจะเน้นความเรียบง่าย รวดเร็ว และเป็นระเบียบตามรูปแบบ Module-based:

src/  
├── assets/             \# รูปภาพ โลโก้ และไฟล์คงที่ของโครงการ  
├── components/         \# คอมโพเนนต์ที่ใช้ร่วมกันในหลายจุด เช่น Buttons, Modals, Tables  
├── config/             \# การตั้งค่าแอปพลิเคชัน และชุดสี Tailwind Custom Palette (Orange-Brown)  
├── features/           \# แบ่งโฟลเดอร์ย่อยตามแต่ละโมดูลหน้าจอ (Module-Based)  
│   ├── planning/       \# กิจกรรม WBS และหน้าจอ Gantt Chart Component  
│   ├── evm/            \# หน้าจอ แดชบอร์ดสรุปประสิทธิภาพ EVM และตัวเลขสถิติ  
│   └── site-logs/      \# บันทึกความคืบหน้ารูปภาพ และบันทึกสภาพอากาศรายวัน  
├── hooks/              \# Custom React Hooks สำหรับเรียกใช้งานร่วมกัน  
├── services/           \# ฟังก์ชันการติดต่อกับ API หลังบ้านผ่าน Axios และ React Query  
├── store/              \# ระบบจัดการ State กลางภายในเครื่อง (Zustand)  
└── utils/              \# ตัวช่วยจัดรูปแบบข้อความ วันที่ และสูตรคณิตศาสตร์ที่จำเป็น

### **4\. แนวทางการออกแบบ UX/UI: โทนสี อารมณ์ และความรู้สึก (Visual Design Strategy)**

ตามโจทย์ความต้องการ "Professional, Futuristic, yet Warm (โทนสีส้ม-น้ำตาลอบอุ่น)" การออกแบบหน้าจอจะลดความแข็งกร้าวของงานวิศวกรรมแบบเดิมลง แล้วแทนที่ด้วยความร่วมสมัย น่าเชื่อถือ และเทคโนโลยีล้ำสมัย:

* **ชุดสีหลัก (Color Palette):**  
  * Primary Orange: \#E26D5C (ส้มอิฐอบอุ่น \- แสดงถึงโครงสร้าง ดินเผา และความมีพลังความก้าวหน้า)  
  * Deep Amber: \#A1523E (สีส้มอมน้ำตาลไหม้ \- สำหรับเน้นย้ำจุดวิกฤต Critical Path หรือเมนูสำคัญ)  
  * Warm Slate/Dark: \#2B2523 (สีน้ำตาลเทาเข้มเกือบดำ \- ใช้เป็นพื้นหลังหลักหรือสีของ Text เพื่อความพรีเมียม สบายตา)  
  * Neutral Light/Warm Gray: \#FDFBF7 (สีขาวงาช้างอุ่น \- พื้นหลังของหน้าจอใช้งานทั่วไปเพื่อลดอาการล้าของสายตาเมื่อจ้องหน้าจอนานๆ)  
  * Accents / Status Indicator: สีเขียวสำหรับงานที่เสร็จสิ้นสมบูรณ์ (\#52B788) และสีฟ้าสว่างสำหรับเครื่องมือพยากรณ์ (\#4EA8DE)  
* **Typography:** ใช้ฟอนต์ไม่มีหัว (Sans-serif) ที่มีความกว้างคงตัวที่จัดเรียงตารางตัวเลขได้ดีเยี่ยม เช่น **Inter** หรือ **IBM Plex Sans Thai** เพื่อรักษากลิ่นอายของความน่าเชื่อถือและความล้ำยุคในเชิงสถาปัตยกรรม  
* **Visual Elements:** การจัดวางการ์ดข้อมูล (Dashboard Card) จะใช้มุมโค้งที่เรียบหรู พร้อมเอฟเฟกต์แสงเงาบางเบา (Soft Shadows) และมีการนำเข้า CSS Glassmorphism เล็กน้อยในส่วนของ Header และ Sidebar
