## 1. ภาพรวมและเป้าหมาย (Vision & Objectives)

CM+ Project Control คือแพลตฟอร์มควบคุมโครงการก่อสร้างระดับองค์กร แบบ "ครบ จบ ในโปรแกรมเดียว"
เข้ามาแทนที่การทำงานแยกส่วนระหว่าง Primavera P6 / MS Project / Excel / กระดาษหน้างาน
เป้าหมายเชิงธุรกิจ (docs/1.): ลดความล่าช้าและต้นทุนบานปลายที่เกิดจาก Data Silos, การประเมิน
ความก้าวหน้าแบบ subjective, การพยากรณ์ต้นทุนที่ผิดพลาด และความล่าช้าในการอนุมัติ VO

**เป้าหมายเชิงเทคนิค (Non-negotiable):**
- WBS tree API ตอบสนอง **< 100 ms**
- Gantt Chart render ได้ลื่นไหลที่ **10,000+ กิจกรรม** (virtualized)
- ทำงานแบบ **Offline-first PWA** สำหรับโมดูลหน้างาน (Photo/Weather/Progress)
- Multi-tenant ที่แยกข้อมูลระหว่างองค์กรได้ 100% (ไม่มีการรั่วไหลข้ามผู้เช่า)
- ผลการคำนวณ CPM/EVM ต้อง reconcile ได้กับ Primavera P6 สำหรับโครงข่ายเดียวกัน

## 5. Domain Engines (สรุปสั้น — รายละเอียดเต็มใน knowledge base)

### CPM Engine
$$EF_i = ES_i + D_i \qquad ES_i = \max_{p \in Pred(i)} \text{constraint}(p,i)$$
$$LS_i = LF_i - D_i \qquad LF_i = \min_{s \in Succ(i)} \text{constraint}(i,s)$$
$$TF_i = LS_i - ES_i \quad;\quad TF_i = 0 \Rightarrow \text{Critical Activity}$$
ทดสอบด้วย fixture ใน `.claude/knowledge/domain/cpm-method.md` (เครือข่าย A→B→D, A→C→D)

### EVM Engine
$$SPI = \frac{EV}{PV} \qquad CPI = \frac{EV}{AC} \qquad EAC = \frac{BAC}{CPI}\ (\text{default variant})$$
Fixture ตัวเลขจริงพร้อม edge case (PV=0, budget=0) ใน `.claude/knowledge/domain/evm-formulas.md`

### Payment / Retention
$$\text{Net Payment} = M \times \frac{\text{progress\%}}{100} - \left(M \times \frac{\text{progress\%}}{100} \times r\right) - \text{advance recovery}$$

## 8. กลยุทธ์การทดสอบ (Testing Strategy)

- **Unit:** ทุกสูตร CPM/EVM ต้องมี test จาก fixture ใน knowledge base (รวม edge case: budget=0,
  PV=0, cycle ใน relation, missing predecessor)
- **Golden-file:** รอบนำเข้า/ส่งออกไฟล์ XER/MSPDI/Excel เทียบค่าอ้างอิงจริงจาก P6/MSP
- **Integration:** ทุก CQRS handler ทดสอบ tenant isolation (tenant A ต้องอ่าน tenant B ไม่ได้)
- **E2E (Playwright):** happy path ต่อหน้าจอ + offline→sync flow ของ Photo/Weather
- **Performance:** WBS API < 100 ms (load test), Gantt ที่ 10,000+ activities (frame rate check)

## 9. ความปลอดภัยและ Multi-tenancy

ตรวจตาม checklist ของ `security-auditor`: tenant isolation ทุก query, JWT/RBAC บังคับใน
Application layer, upload surface (XER/MPP/XLSX/photo) เป็น untrusted input, CSV/Excel export
ป้องกัน formula injection, audit log ครบทุก mutation

## 10. DevOps & Deployment

Docker multi-stage (SDK→runtime .NET, node build→nginx สำหรับ PWA), GitHub Actions
(build+test+lint+security scan ทุก PR), gated promotion dev→staging→production ด้วยการอนุมัติ
มนุษย์, EF migration เป็นขั้นตอนแยกที่ต้องอนุมัติก่อน apply บน production
